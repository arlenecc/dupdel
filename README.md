# DupDel · 重复文件清理器（macOS）

一个基于 SwiftUI 的 macOS 原生工具：选择任意目录后自动遍历其子目录，用 SHA-256 内容哈希做**全局统一排重**（跨所有子目录，不局限于同级目录），保留每组中「创建或修改日期最新」的一份，删除其余副本；若删除后目录变空则一并回收空目录。

- 界面：上方 1/4 配置区，下方 3/4 处理过程区，底部状态栏显示总体进度
- 性能：分级哈希 + 受限并发 + 后台队列，面向海量文件场景设计
- 安全：绝不删除所选目录之外的文件，根目录自身不会被删除，清理前有二次确认

## 一、功能特性

| 能力 | 说明 |
| --- | --- |
| 目录选择 | 支持 `NSOpenPanel` 选择或直接粘贴路径，可一键在 Finder 中打开 |

| 全局排重 | 跨全部子目录统一计算，只看文件内容，与文件名/后缀/所在目录无关 |
| 保留策略 | 每组保留 `max(创建时间, 修改时间)` 最新的一份，日期相同按路径稳定决胜 |
| 预估统计 | 分析完成后给出文件总数、总占用、重复组数、冗余文件数、可回收空间，以及清理后的文件数与空间 |

| 空目录回收 | 删除后目录为空则删除，并级联向上回收（可关闭） |
| 删除方式 | 直接删除，或先移到废纸篓（可切换） |
| 过滤选项 | 包含隐藏文件、忽略 0 字节文件、最小文件体积、哈希并发度（自动/2/4/8） |
| 过程可见 | 处理日志实时滚动输出，状态栏显示阶段进度与耗时 |
| 随时中止 | 分析、清理均可在任意时刻取消，取消点细到单个文件 |

## 三、快速开始

### 环境

- macOS 14+（Apple Silicon 或 Intel）
- Swift 6（SwiftPM），无需 Xcode

### 运行

```bash
swift build                 # 调试构建
swift run DupDel            # 直接运行

./scripts/make_app.sh       # 生成 dist/DupDel.app
open dist/DupDel.app
```

### 打包分发

```bash
./scripts/make_dmg.sh
# -> dist/DupDel-1.0.0.dmg （1.3 MB，含 App + Applications 拖拽安装）
```

产物说明：

- 默认构建 **arm64 + x86_64 通用二进制**（`DUPDEL_ARCHS=arm64` 可只出 Apple Silicon 版）
- 图标由 `scripts/make_icon.swift` 用 CoreGraphics 程序化绘制，输出 10 个尺寸后由 `iconutil` 合成 `AppIcon.icns`
- 已做 ad-hoc 代码签名并通过 `codesign --verify --deep --strict`；DMG 经 `hdiutil verify` 校验
- 未使用 Apple 开发者证书，他人首次打开需右键「打开」或在「隐私与安全性」中允许；正式分发可把脚本里的 `codesign --sign -` 换成 Developer ID 并做 `notarytool` 公证

## 四、使用步骤

1. 点击「选择…」挑取目标目录（或粘贴路径）
2. 按需调整过滤项：包含隐藏文件、忽略 0 字节文件、最小体积、并发度
3. 点击「开始分析」，等待状态栏进度走完
4. 查看统计条：文件总数/总占用、重复组与可回收空间、**清理后预估**
5. 展开下方「重复文件清单」核对每组（绿色标记的一份会被保留）
6. 点击右侧「开始清理」，二次确认后执行；完成后统计条刷新为清理后的实际值

> 注意：删除默认是不可恢复的直接删除（可勾选「删除前移到废纸篓」，更安全但大量文件时更慢）。

## 五、实现原理

### 分析流程（`DupDelCore`）

```
扫描（1 次遍历）
  └─ 记录文件数、总字节，按「文件体积」分桶，只保留同体积 ≥2 的桶
        ↓
部分哈希（只读取前 64 KB）
  └─ 淘汰掉绝大部分「体积相同但内容不同」的文件
        ↓
完整哈希（仅对部分哈希冲突者）
  └─ SHA-256 全量校验，确认内容完全相同
        ↓
分组 → 选出保留者 → 按可回收空间排序
```

- **体积先行**：只有体积相同的文件才可能是重复，这一步几乎零 I/O 就排除掉绝大多数文件
- **分级哈希**：先读 64 KB 快速比对，只有冲突才读全文件；`size ≤ 64 KB` 时部分哈希即完整哈希，直接跳过第二阶段
- **分组键含体积**：不同体积的文件前 64 KB 可能完全相同，避免跨体积误判

### 清理流程

1. 收集每组冗余副本，逐个校验路径必须位于所选目录之内（安全护栏）
2. 逐个删除（或移入废纸篓），记录实际删除数与回收字节
3. 自底向上检查受影响目录，为空则删除并继续向上，根目录本身永不删除

### 性能与资源控制

| 措施 | 作用 |
| --- | --- |
| 后台队列执行重活（`Background.run`） | 不占用 Swift 协作线程池，界面与其他任务不卡顿 |
| 分块派发的受限并发（默认 2~8） | 避免海量文件产生海量任务，避免磁盘抖动 |
| 扫描进度每 500 个文件回调一次 + 0.12s 节流 | UI 不被高频刷新压垮 |
| 清理事件后台侧先节流（0.1s）再投递主线程 | 10 万文件也不会产生 10 万次主线程派发 |
| POSIX `read` + 按实际读量分配复用缓冲区 | 避免每个文件分配并清零 1 MB 缓冲（实测 30,000 文件 6.2s → 0.70s） |
| 读取量 > 8 MB 时开启 `F_NOCACHE` | 扫描大文件不冲刷系统页缓存 |
| 分桶结束即释放唯一体积数据 | 降低峰值内存 |
| 失败/异常明细设上限（64 / 512 / 256） | 极端场景不会内存膨胀 |
| 列表只渲染前 2,000 组、日志上限 3,000 条 | 界面始终流畅 |
| 取消点细到单个文件 | 大文件哈希/批量删除都能及时停下 |

实测（本机 Apple Silicon）：30,000 个文件（5,000 组重复）分析耗时约 **0.70s**；3 个 256 MB 大文件完整哈希约 **0.14s**。

## 八、注意事项

- **符号链接一律跳过**，不做跟随（避免循环与越界删除）
- **0 字节文件默认忽略**，避免误删 `.gitkeep` 之类的占位文件；需要排重空文件可在配置区关闭该选项
- **隐藏文件默认跳过**（如 `.git`），可在配置区开启
- 硬链接指向同一内容时会被视为重复副本，删除其一不影响另一份数据
- 路径中的 firmlink（如 `/var` → `/private/var`）已统一用 `realpath` 规范化，前缀判断与空目录回收均可靠
- 分析进行中禁止修改目录；切换目录会自动清空上一次的结果
- 若存在删除失败的文件（常见于权限问题），列表会保留以便修复后重试
